# Recommended Build Order

## Phase A — Product shell and UX spine
1. Repo/auth/database/CI.
2. Parent four-destination shell.
3. Child four-destination shell.
4. State-driven Home/Today service.
5. Contextual empty/error states.

## Phase B — Curriculum and question bank
6. P3 Maths curriculum/provenance.
7. Question-bank schema/admin/review.
8. Enough approved questions for multiple mocks.

## Phase C — Prepare and generate
9. Child/assessment setup.
10. Manual scope selection.
11. Recommended blueprint internally.
12. `Customise` advanced options.
13. Deterministic paper selection.
14. Printable PDF + answer pack.

## Phase D — Child mock
15. Dedicated iPad Mock Mode.
16. Autosave and unanswered review.
17. Result shell.

## Phase E — Smart input and marking
18. School-notice upload/extraction.
19. Print-paper upload.
20. Deterministic marking.
21. AI-assisted marking with review.
22. Marked-paper split-view UX.

## Phase F — Learning loop
23. Mastery.
24. Targeted practice.
25. Adaptive next mock.

## Phase G — Motivation
26. Reward policy and ledger.
27. Anti-farming RewardEngine.
28. Child points experience.
29. Parent reward catalogue/redemption.

## Release discipline
Run usability tests after the first complete Prepare -> Mock flow and again after Mark -> Review -> Practice. Do not wait until every feature is finished.
